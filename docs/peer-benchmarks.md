# v0.2 peer comparison

Archived v0.2 measurements. See the [v0.3 performance report](performance-v0.3.md)
for the revised parser, lazy cache loading and repeated-query comparisons.

Measured on 5 October 2026. The goal is to expose useful strengths and tradeoffs,
not to claim that one engine wins every workload.

The biggest observed advantage is a small edit in a large multi-sheet workbook:
SheetJet copies untouched compressed members instead of loading and resaving their
cells. Cold flat-table reading is a different task: Calamine and Polars win that
comparison. Direct Polars-Parquet also wins the measured cached aggregation.

## Million-row workbook with shared strings

Four selected sheets, 250,000 transaction rows each, five columns, plus an assumptions
sheet and an excluded hidden sheet. The 24,691,884-byte workbook uses shared strings,
generated by XlsxWriter. **One trial per method**: this is a scale check, not a stable
estimate across machines. [Raw trials, versions, and fixture SHA-256](benchmarks/peers-million.json).

| Task / method | Seconds | Peak RSS, MiB |
|---|---:|---:|
| One assumption edit: SheetJet | **0.174** | **36.0** |
| One assumption edit: openpyxl load/save | 123.858 | 2,031.4 |
| Cold aggregation: SheetJet | 21.638 | 125.9 |
| Cold aggregation: openpyxl read-only | 35.105 | 66.6 |
| Cold aggregation: pandas/openpyxl | 48.836 | 237.7 |
| Cold aggregation: pandas/Calamine | 7.524 | 478.4 |
| Cold aggregation: Polars/Calamine | **2.334** | 177.8 |
| Cold aggregation: python-calamine + Python grouping | 2.432 | 152.5 |
| Cached projection: new SheetJet workbook session | 0.337 | 129.0 |
| Cached projection: Polars-Parquet | **0.011** | 178.0 |

The edit changes `Assumptions!B1`, **not a cell inside a large transaction sheet**.
SheetJet's timing includes changed-cell/package validation and an audit sidecar.
Both saved values are independently checked after timing. The byte-preservation
contract is separately tested on opaque parts, charts/pivots, a macro canary, and ZIP
edge cases. This does not establish native Excel rendering or functioning VBA behavior.

Cached rows exclude cache creation and imports from their timed phase. Preparing the
SheetJet projection took 20.804 s; preparing the Polars-Parquet cache took 1.743 s.
Peak RSS includes preparation and post-timing validation, so cached memory is not the
incremental memory of a reopened session. Cached and cold timings are not interchangeable.

## 100,000 rows, three trials per method

Four selected sheets with 25,000 rows each, using inline strings. Medians from three
fresh subprocesses per method, in fixed randomized order.
[All 30 trials and fixture hash](benchmarks/peers-100k.json).

| Task / method | Median seconds | Median peak RSS, MiB |
|---|---:|---:|
| One assumption edit: SheetJet | **0.126** | **38.2** |
| One assumption edit: openpyxl load/save | 10.849 | 258.9 |
| Cold aggregation: SheetJet | 2.036 | 115.6 |
| Cold aggregation: openpyxl read-only | 2.951 | 48.0 |
| Cold aggregation: pandas/openpyxl | 5.027 | 122.7 |
| Cold aggregation: pandas/Calamine | 0.779 | 128.0 |
| Cold aggregation: Polars/Calamine | 0.681 | 76.6 |
| Cold aggregation: python-calamine + Python grouping | **0.266** | 36.6 |
| Cached projection: new SheetJet workbook session | 0.117 | 120.2 |
| Cached projection: Polars-Parquet | **0.008** | 85.9 |

Each aggregate result matched independent fixture arithmetic. Library initialization
is included in cold results and matters at this size. Edit timings and RSS have
visible trial-to-trial variation; see the raw values instead of treating a ratio as
a hardware-independent guarantee.

## Reproduce

```console
python -m pip install -e ".[test,benchmark]"
python -m benchmarks.peers --rows 25000 --sheets 4 --repeats 3 --output benchmark-output/peers-100k/results.json
python -m benchmarks.peers --rows 250000 --sheets 4 --repeats 1 --shared-strings --output benchmark-output/peers-million/results.json
```

Use `--methods` to select a subset, for example `--methods sheetjet polars_calamine`.
`--workbook` reuses a generated fixture and requires matching `--rows`/`--sheets`.
This runner expects its deterministic fixture schema; it is not a benchmark adapter
for arbitrary private workbooks. All raw reports retain per-trial answers and checks.

## Methodology and boundaries

- Fresh subprocess per trial, fixed randomized method order, OS file cache not flushed.
- Cold time includes relevant imports, workbook reading, selected-column processing,
  aggregation and workbook close. Fixture generation, temporary-directory cleanup and
  independent saved-value/answer validation are excluded.
- Same selected sheets and input columns for every aggregate; totals checked against
  independent arithmetic from the fixture definition. Hidden notes are excluded.
- CSV/Parquet staging is included in SheetJet cold measurements; persistent cache
  creation is not free. Both cached workflows report preparation separately.
- RSS sampled every 10 ms; native allocations are included but brief spikes can be
  missed. Imports and allocator retention affect memory figures.
- All peers return the same small aggregate. Context reduction versus dumping an
  entire sheet is not credited as a unique parser advantage.
- Synthetic integer transaction data does not cover arbitrary formulas, Excel dates,
  merged regions, external links or messy production data. Those require contract
  tests and representative user fixtures, not speed inference from this dataset.
- The first 100k engineering run included a formula-translator import in the patch
  path; the final 100k report was rerun after making that import conditional. Reports
  here include only the final 100k run and the explicitly labeled million-row trial.

Polars uses the Rust Calamine parser through fastexcel for its default Excel reader,
according to its [Excel guide](https://docs.pola.rs/user-guide/io/excel/). The separate
[python-calamine binding](https://pypi.org/project/python-calamine/) provides another
native-reader baseline. These engines have different value, error and formula-cache
interfaces; SheetJet does not bypass its own checks to match their throughput.

## What follows from the evidence

Use SheetJet when exact edits, source-part preservation, bounded agent responses,
formula-aware rejection and per-sheet reuse matter. For a first, uncomplicated table
read, native Calamine/Polars currently has the performance advantage. If a dataset is
already Parquet and no Excel-specific controls are needed, direct Polars is the faster
measured route. There is no evidence here for “best in all aspects,” and no such claim
is made.
