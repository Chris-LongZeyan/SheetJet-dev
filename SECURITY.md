# Security and file access

SheetJet processes local workbooks and does not provide a network service. Workbook
cells, formulas, metadata, CLI arguments generated by agents, and submitted benchmark
programs must be treated as untrusted input.

## CLI workspace policy

As of 0.6.1, all CLI input, output, cache, patch, range, schema, and reconciliation
spec paths must resolve within `--workspace`, which defaults to the current
directory. Relative paths are interpreted against that root. The policy resolves
existing ancestors strictly, checks containment by path components, and rejects
existing symlink escapes, broken links, Windows device names, and alternate streams.
It does not silently fall back to lexical containment if canonicalization fails.

Use a narrow root selected by the trusted caller. An agent integration must control
the root and permitted operations rather than letting an untrusted prompt select a
broader root. CLI checks are not an OS sandbox: they do not defend against concurrent
filesystem replacement or another process changing links after validation. Hard
links inherit filesystem permissions and cannot establish exclusive file ownership.
Use OS isolation for hostile inputs or untrusted execution.

The Python library does not impose a workspace root. Programmatic callers retain
responsibility for access policy. Reconciliation refuses to replace either input
and publishes complete exports atomically; these guarantees do not replace process
isolation. Caches and audit/export files contain source-derived data.

## Historical benchmark code

`benchmarks/submissions/` contains four frozen implementations from past agent trials.
Their byte hashes are evidence, and they are not supported product implementations.
They contain historical limitations, including fixed temporary paths and permissive
parsing. Run reproductions only in an isolated disposable environment using synthetic
fixtures. Do not use these programs on confidential or untrusted production files.

The SonarQube scope explicitly excludes those four files while retaining maintained
benchmark runners, source code, examples, and tests. The quality gate and rules are
unchanged. Published historical performance reports describe their recorded commits,
not an assertion that old submissions meet the current quality gate.

## Reporting a vulnerability

Use the repository's private vulnerability-reporting channel when available. If it
is unavailable, request a private contact without posting exploit inputs or sensitive
workbooks publicly. Include the affected version, entry point, a minimal synthetic
reproduction, and the expected access or preservation boundary.
